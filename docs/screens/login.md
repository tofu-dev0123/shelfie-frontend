# ログイン画面

## 概要

| 項目 | 内容 |
|---|---|
| 画面名 | ログイン |
| 目的 | Google / GitHub アカウントでログインする |
| URL パス | `/login` |
| クエリパラメータ | `redirect` — ログイン後のリダイレクト先パス（省略時はホームへ） |
| 認証 | 不要 |

## UI要素

| 要素 | 種別 | 説明 |
|---|---|---|
| アプリロゴ | 画像 | Shelfie のロゴ |
| 見出し | テキスト | 「ログイン」 |
| Google でログインボタン | ボタン | Clerk の Google OAuth を起動 |
| GitHub でログインボタン | ボタン | Clerk の GitHub OAuth を起動 |
| サインアップへのリンク | リンク | 「アカウントをお持ちでない方はこちら」→ `/signup` |

## インタラクション・動作フロー

1. ユーザーが「Google でログイン」または「GitHub でログイン」をクリックする
2. Clerk の OAuth フローが起動し、各プロバイダーの認証画面へ遷移する
3. 認証成功後、Clerk JWT を取得する
4. Clerk JWT を Rails `/v1/auth/login` に送信する
5. Rails がアクセストークン（レスポンスボディ）とリフレッシュトークン（HttpOnly Cookie）を発行する
6. アクセストークンを Zustand ストアに保存する
7. `redirect` クエリパラメータがあればそのパスへ、なければホーム（`/`）へリダイレクトする
8. Rails が 404 を返した場合（アカウント未登録）、`/signup` へリダイレクトする

## エラーハンドリング

| エラーケース | 対応 |
|---|---|
| OAuth 認証キャンセル | ログイン画面に留まる（Clerk が処理） |
| Rails `/v1/auth/login` が 401 | トースト通知「認証に失敗しました。再度お試しください。」 |
| Rails `/v1/auth/login` が 404 | `/signup` へリダイレクト（アカウント未登録） |
| Rails `/v1/auth/login` が 500 | トースト通知「ログインに失敗しました。しばらく経ってから再度お試しください。」 |

## 関連画面・遷移先

| 遷移先 | 条件 |
|---|---|
| ホーム（`/`） | ログイン成功（`redirect` パラメータなし） |
| `redirect` パラメータのパス | ログイン成功（`redirect` パラメータあり） |
| サインアップ（`/signup`） | ログイン成功かつ初回登録ユーザー |
