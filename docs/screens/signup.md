# サインアップ画面（プロフィール設定）

## 概要

| 項目             | 内容                                                  |
| ---------------- | ----------------------------------------------------- |
| 画面名           | サインアップ（プロフィール設定）                      |
| 目的             | 初回登録時に nickname / username を設定する           |
| URL パス         | `/signup`                                             |
| クエリパラメータ | なし                                                  |
| 認証             | 不要                                                  |

## UI要素

### Clerk 未認証時

| 要素                    | 種別     | 説明                             |
| ----------------------- | -------- | -------------------------------- |
| アプリロゴ              | 画像     | Shelfie のロゴ                   |
| 見出し                  | テキスト | 「はじめる」                     |
| Google でサインアップボタン | ボタン | Clerk の Google OAuth を起動     |
| GitHub でサインアップボタン | ボタン | Clerk の GitHub OAuth を起動     |
| ログインへのリンク      | リンク   | 「すでにアカウントをお持ちの方はこちら」→ `/login` |

### Clerk 認証済み時（プロフィール設定フォーム）

| 要素                   | 種別         | 説明                                                           |
| ---------------------- | ------------ | -------------------------------------------------------------- |
| アプリロゴ             | 画像         | Shelfie のロゴ                                                 |
| 見出し                 | テキスト     | 「プロフィールを設定しましょう」                               |
| ユーザー名フィールド   | テキスト入力 | `username` — ログイン ID となるユーザー名（英数字・アンダースコア） |
| ユーザー名の説明文     | テキスト     | 「他のユーザーに表示される ID です（変更不可）」               |
| ニックネームフィールド | テキスト入力 | `nickname` — 表示名として使用される名前                        |
| バリデーションエラー   | テキスト     | 各フィールドの直下に表示する                                   |
| 送信ボタン             | ボタン       | 「はじめる」— 送信中は `disabled` かつ「送信中...」に変化      |

## インタラクション・動作フロー

### パターン A: Clerk 未認証でアクセスした場合

1. OAuth ボタン（Google / GitHub）が表示される
2. ユーザーがいずれかをクリックする
3. Clerk の OAuth フローが起動し、各プロバイダーの認証画面へ遷移する
4. 認証成功後、Clerk JWT を取得する
5. Clerk JWT を Rails `POST /v1/auth/login` に送信する
6. レスポンスに応じて分岐する：
   - **404（新規ユーザー）**: プロフィール設定フォームを表示する（`/signup` のまま）
   - **200（既存ユーザー）**: アクセストークンを Zustand ストアに保存し、ホーム（`/`）へリダイレクトする

### パターン B: Clerk 認証済みでアクセスした場合（ログイン画面経由）

1. プロフィール設定フォームが表示される
2. ユーザーがユーザー名・ニックネームを入力する
3. 「はじめる」ボタンをクリックする
4. Zod バリデーションを実行する（クライアントサイド）
5. バリデーションエラーがある場合は各フィールド直下にエラーメッセージを表示し、送信を止める
6. バリデーションを通過したら `useAuth().getToken()` で Clerk JWT を取得する
7. Clerk JWT + フォームデータを Rails `POST /v1/auth/signup` に送信する
8. Rails がアクセストークンとリフレッシュトークンを返す
9. アクセストークンを Zustand ストア（`authStore`）に保存する
10. ホーム（`/`）へリダイレクトする

## バリデーションルール

| フィールド | ルール                                                         |
| ---------- | -------------------------------------------------------------- |
| `username` | 必須 / 3 文字以上 20 文字以下 / 半角英数字・アンダースコアのみ |
| `nickname` | 必須 / 1 文字以上 50 文字以下                                  |

## エラーハンドリング

| エラーケース                           | 対応                                                                              |
| -------------------------------------- | --------------------------------------------------------------------------------- |
| OAuth 認証キャンセル                   | サインアップ画面に留まる（Clerk が処理）                                          |
| Rails `POST /v1/auth/login` が 401     | トースト通知「認証に失敗しました。再度お試しください。」                          |
| Rails `POST /v1/auth/login` が 500     | トースト通知「ログインに失敗しました。しばらく経ってから再度お試しください。」    |
| Clerk JWT の取得失敗                   | トースト通知「サインアップに失敗しました」                                        |
| Rails `POST /v1/auth/signup` が 422    | トースト通知「入力内容に誤りがあります。ご確認ください。」（ユーザー名重複など）  |
| Rails `POST /v1/auth/signup` が 500    | トースト通知「サインアップに失敗しました。しばらく経ってから再度お試しください。」 |

## 処理詳細

### OAuth 後の振り分け処理（パターン A）

1. Clerk の OAuth 完了後、`useAuth().getToken()` で Clerk JWT を取得する
2. Clerk JWT を `lib/api/auth.ts` の `login()` に渡す
3. `login()` は Rails `POST /v1/auth/login` にリクエストを送信する
4. レスポンスに応じて以下を実行する：
   - **200**: アクセストークンを Zustand ストアに保存しホーム（`/`）へリダイレクトする
   - **404**: プロフィール設定フォームを表示する（新規ユーザーとして扱う）
   - **401 / 500**: トースト通知を表示する

### サインアップ処理（パターン B）

1. `useAuth().getToken()` で Clerk JWT を取得する（既存セッションから）
2. フォームデータ `{ username, nickname }` と Clerk JWT を `lib/api/auth.ts` の `signup()` に渡す
3. `signup()` は `serverPost` を使って Rails `POST /v1/auth/signup` にリクエストを送信する
4. レスポンスに応じて以下を実行する：
   - **201**: アクセストークンを Zustand ストアに保存しホーム（`/`）へリダイレクトする。リフレッシュトークンは Rails が HttpOnly Cookie にセットする（フロント側の操作不要）
   - **422**: トースト通知「入力内容に誤りがあります。ご確認ください。」を表示する
   - **500**: トースト通知「サインアップに失敗しました。しばらく経ってから再度お試しください。」を表示する

| 遷移先                  | 条件                                                              |
| ----------------------- | ----------------------------------------------------------------- |
| サインアップ（`/signup`） | ログイン画面で OAuth 認証後、Rails にユーザーが存在しない（404）  |
| サインアップ（`/signup`） | ログイン画面の「アカウントをお持ちでない方はこちら」リンクをクリック |
| ホーム（`/`）           | サインアップ成功 / OAuth 認証後に既存ユーザーと判明               |
| ログイン（`/login`）    | 「すでにアカウントをお持ちの方はこちら」リンクをクリック          |
