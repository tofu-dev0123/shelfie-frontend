# create-mock スキル

Shelfieプロジェクトの画面モックをPNGとして生成する。

## フロー

### ステップ0: 出力ディレクトリの確認

スキル起動時にユーザーから出力ディレクトリ名を受け取る。

- ユーザーが指定した場合: その値を `{ディレクトリ名}` として使用する
- 指定がない場合: 「出力先ディレクトリ名を教えてください（例: `v1`）」と聞く

出力先は `docs/mocks/{ディレクトリ名}/` になる。

### ステップ1: 画面選択

`docs/screens.md` を読み込んで画面一覧を表示し、ユーザーにどの画面のモックを作るか選択させる。

### ステップ2: 設計書の読み込み

選択された画面の設計書ファイルを読む。

- ファイルパス: `docs/screens/{画面のファイル名}.md`
- ファイルが存在しない場合は「設計書がまだ作成されていません」とユーザーに伝え、基本情報（画面名・パス・説明）だけで進めるか確認する

### ステップ3: デザインシステムの参照

`.claude/rules/DESIGN.md` を読んでデザイントークンを把握する。モックのHTML/CSSには必ずこのトークンに定義されたカラー・タイポグラフィ・スペーシング・角丸などの値を使う。

### ステップ4: レイアウト相談

設計書の内容を踏まえて、以下の点についてユーザーと相談する。

- **レイアウト**: コンポーネントの配置・構成
- **表示内容**: ダミーデータの内容（ユーザー名・書籍タイトルなど）
- **状態**: ログイン済み/未ログイン、データあり/なし など

相談内容はまとめて一度に聞く。ユーザーから十分な方針が得られたら次のステップへ進む。

### ステップ5: HTML/CSSの生成

以下の仕様でHTMLファイルを作成する。

**出力先**: `/tmp/{画面名}-mock.html`

**HTML作成ルール**:
- デザイントークンはCSS変数として `:root` に定義し、実際の値（px・カラーコードなど）をセットする
- フォントは Inter を Google Fonts から読み込む: `<link href="https://fonts.googleapis.com/css2?family=Inter:wght@400;500;600;700;800&display=swap" rel="stylesheet">`
- ビューポート幅: 1280px を基準にデスクトップレイアウトを作る
- ダミーデータは現実的な日本語コンテンツで埋める（「テストユーザー」「サンプル本」などは避け、実際の本のタイトルや著者名を使う）
- 書影のプレースホルダーは `background: var(--color-gray-100); border: 1px solid var(--color-gray-200)` で表現する
- Headerは全画面共通で入れる（ロゴ「Shelfie」＋ナビリンク）

**CSS作成ルール**:
- DESIGN.mdのデザイン原則（Contrast・Repetition・Alignment・Proximity）に従う
- フラットデザイン。ボーダーで区切り、影は原則使わない（ホバー時のみ `--shadow-hover`）
- すべてのスタイルはインラインの `<style>` タグに記述する

### ステップ6: スクリーンショット撮影

レイアウト仕様は `.claude/skills/create-mock/references/layout.md` を参照する。

```bash
npx playwright screenshot \
  --browser chromium \
  --viewport-size "1720,900" \
  --full-page \
  /tmp/{画面名}-mock.html \
  docs/mocks/{ディレクトリ名}/{画面名}-mock.png
```

`docs/mocks/{ディレクトリ名}/` ディレクトリが存在しない場合は事前に作成する。

### ステップ7: 完了報告

生成されたPNGファイルのパス（`docs/mocks/{ディレクトリ名}/{画面名}-mock.png`）をユーザーに伝える。
HTMLファイル（`/tmp/{画面名}-mock.html`）はそのまま残しておく（ユーザーが確認できるように）。
